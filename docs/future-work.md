# Remaining work after the feature upgrade

Updated on 20 October 2026. The user subsequently authorized implementation of the features identified in the three-prototype comparison. That upgrade is recorded in [Feature upgrade](feature-upgrade.md); the earlier comparison is retained as a [baseline audit](feature-comparison-audit.md).

## Implemented from the comparison

Weekly plans, guided setup and interests, multiple-plan management, template generation and preview, practice access, six lab models, seven standalone coding challenges, interview review/history, a learner dashboard, bookmarks, rewards, expanded search/filtering, narration controls, reference topics, a general playground, undo completion and progress reset/undo are implemented.

## Still pending beyond peer-feature parity

1. Configure and validate a live AI provider end to end. Local templates and phrase-based review cues do not replace this validation.
2. Add real authentication, server-side authorization and a shared database for classrooms and participation across devices.
3. Develop generative narration, full animations and custom media uploads, with review of generated teaching material.
4. Collect feedback from real learners and instructors; assess the usefulness and accuracy of the courses and activities.
5. Extend instructor editing of lab parameters and coding test contracts, and prepare team deliverables and contribution evidence.

C/C++ and Python output traces intentionally support only a small stated subset; full language runtimes would be a separate extension. All existing local learner records, personally edited courses, classroom rosters and language preferences must continue to be preserved.
