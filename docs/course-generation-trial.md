# 分镜生成试验（2026-11-04）

本次目标是把现有原创课件的案例、分步讲解、SVG 绘图组件和播放器用于用户生成，而不是承诺模型能复制每页人工编排的画面。

## 已实现

- `production: "storyboard-v1"` 为显式试验入口，原默认生成流程保持兼容，未默认切换所有用户。
- 先生成包含受众、可观察目标、贯穿案例和课节步骤的教学简报，再写完整讲解与分镜。
- 分镜是有界 JSON：角色、动作、可观察结果、状态和总结。支持过程、对话、前后变化三种布局；复用 `lesson-art-kit.js` 的人物、助手、手机、文档、数据库等组件，并加入区块、链条图形。
- `teachingLessonForPlayer` 使用真实播放进度逐步显示动作；文档模式与导出使用同一分镜最终帧。
- 局部分镜错误只修复对应页；目标格式、角色引用、未知字段、文字边界等有明确校验。
- 内容复核与结构校验分开。发现内容问题时只修复被标记的页，修复后再次检查；复核不通过则返回失败，不静默退回旧框图。
- 存储和编辑适配器保留分镜；迁移 `202611050004_storyboard_courseware.sql` 扩展校验，保留旧课程、质量字段和扩展模板。云端验证：有效分镜、动画课程、旧课程均通过，无效角色引用被拒绝。

## 真实提供商实测及限制

使用已有智谱配置测试 Alice 向 Bob 转账的英语入门课，未替换服务商、未更换为付费模型。主模型出现限流时使用原有免费备用模型。确实获得了四页带角色和动作的课件，经过局部格式修复后结构检查通过。

但第一次完整自动生成链路仍返回 `invalid_ai_result`，不能声称已经稳定达到原有 45 节课质量。实测还出现“每个节点都会保存交易”“所有链都采用挖矿”“入块等于永久不可变”等过度概括。模型的自我复核也不可靠，可能只是补一句免责声明而没有删掉相互矛盾的句子。因此暂不默认推广试验入口。

`#courseware-example` 是真实模型输出经过资料校对后的可播放样板；页面明确说明已校对，不将人工纠正后的结果冒充完全自动生成成功。样板参考：

- https://ethereum.org/developers/docs/consensus-mechanisms/pos/
- https://ethereum.org/developers/docs/consensus-mechanisms/pow/

自动复核只能发现部分问题，不是事实正确、教学有效或达到学习目标的证明。下一步推广的前提应是多个题材重复测试都通过，并检查实际画面和知识准确性；不能只以 JSON 能解析或页面能播放为验收标准。

## 运行限制

分镜试验的 API 总预算为 275 秒，Vercel 函数上限配置为 300 秒，需要部署环境支持 Fluid compute 对应时限。原非分镜请求保留原有短预算。开发服务器需重新载入后才使用新 API 实现；本次没有发布网站或提交代码。

## 用户生成链路：lesson-v2

教师工作台和学习路径通过共享 `cloudAPI` 为课件请求指定 `production: lesson-v2`；大纲仍走原流程。此模式保留现有课程保存格式和播放器，不强制复杂的动画分镜协议。

1. AI 先生成受众、可观察目标、贯穿案例、4–6 页教学顺序及画面意图。
2. 每页单独请求，带入同一设计和已完成页面的讲解；AI 选择既有插画场景和具体标签。格式失败仅重试该页一次。
3. 根据完成的课件生成学习目标、误区和两道选择题。
4. 另一次 AI 调用复核整节；只允许修复被指出的页面，之后再复核。仍失败则不放行。

不会把格式正确当成事实正确，复核也不是权威事实保证。不会在复核失败时静默退回旧的一次生成方式。继续使用原配置模型及原免费备用模型，不新增供应商或付费模型。

失败请求的设计、已验证页面和题目在当前服务实例内缓存十分钟，上限二十项，缓存键包含认证用户和完整输入。成功后清除；服务重启、跨实例或缓存到期后不保证恢复。此机制不是持久化任务队列，浏览器刷新/关闭仍会中断当前客户端任务。

自动化验证覆盖逐页失败重试、共享案例、复核后局部修复、禁止改动未标记页面、复核持续失败拦截、失败请求复用已完成页面、共享调用入口及认证 API。真实模型仍需以实际运行结果评价，不以模拟测试替代质量验证。

实测记录：免费备用模型可跑通一份四页 Git 课件，但普通复核漏掉了提交后 `git status` 状态错误和把桌面操作画成手机的问题。因此又增加了独立的状态顺序、命令输出及配图对应检查；不能把模型的 `pass: true` 当成权威事实认证。区块链样例曾在复核/格式阶段失败，未写入用户课程。

针对备用模型把批量修复索引写错的问题，`lesson-v2` 的修复请求进一步拆成“一次只修一页”：服务端决定目标位置，模型只返回完整单页，不能提交其他页索引。未被复核标记的页面不会交给修复请求修改。复核通过后还需执行状态顺序与插画匹配的独立审查。
